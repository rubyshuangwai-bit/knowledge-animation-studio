# 句尾完整性与换镜收尾

适用于每次新配音、换声或替换台词，检查对象是每个合成知识段的末句，以及成片对应的镜头/章节交界。不能只检查整片最终一秒。

## 本次发现与证据边界

推理框架案例中，章节保留了各段完整PCM，合并与编码没有解释性的语音裁短；原始配音末端已经存在明显能量、缺少自然收尾缓冲。若干末字识别也不完整，但ASR不能证明实际漏字。镜头间仅补0.12秒静音不足以修复这种情况。

结论限于：原音频硬收尾值得复核，不能归咎于画面转场裁音；尚未证明具体TTS内核、解码、停止机制哪一处有错。波形到达文件边界不自动意味着少了字，波形平稳也不证明话说全了。不要直接全局改底层库或宣称模型已定位为根因。

## 配音到渲染前的处理顺序

1. 保留原始生成音频与参数，检查末句尤其最后几个字是否完整、末韵是否被截、语气是否自然结束。与批准稿核对，可用独立ASR作辅助；不能用全文匹配率代替末句复核。新主题先选一段包含实际术语和完整末句的试听样本。
2. 用`scripts/audio_endings.py audit`逐段筛查。默认10毫秒能量窗、适应当前响度的阈值：不足80毫秒的安静尾段提示复核，不足350毫秒提示缓冲不足。这是保守的工程筛查值，不是语言学断音鉴定；音乐、底噪、耳语应先分离纯旁白或人工核对。静音文件不能视为合格旁白。
3. **疑似缺字、末韵硬截或完整性未确认：重做该合成段。**先查生成token预算、停止原因（如工具提供）、是否收齐最后输出块/解码尾部，以及人工裁切/去静音。确认模型、参考音频、参考稿和采样率一致。必要时用更完整的知识段边界、自然句末标点重试；不偷偷改正文、换人声或整体降速。单段最多先试两次有依据的变更，仍失败就停在配音阶段，说明具体问题，不无限生成或先把疑似缺字片段送去渲染。
4. **经实际试听确认话已说完，只是结束太急：**可另存派生音轨，按需要补足约0.35–0.6秒缓冲（工具默认0.45秒），保留原样采样。不用长静音、淡出正在发音的片段或强制字幕延长来掩盖缺字。自动程序不能替助手伪造`listened_complete`。
5. 若重生成，重新做ASR/人工时间定位和全部受影响字幕、语义事件。只在末端补静音时，原句内时间不变，但镜头时长和后续累计时间必须按新音频重建。保持当前画面到句尾完成及必要停留后再转场，不按字幕最后一个时间提前剪音频。
6. `build`与后续构建有效性检查会检查音频结尾。疑似硬收尾若无当前音频hash对应的末句试听记录，会停止；总缓冲不足0.35秒也会停止。经语义停顿处理后的音频还要追查`raw_audio`的结尾，不能靠尾部补零消掉原始警告。TTS适配器会输出`.ending.json`，不会自动宣称语句完整。
7. 渲染后复核实际交界：每类转场的代表位置、所有被标记过的段落和章节尾。对比原音频、章节PCM和成片，确认没有额外裁切、重叠或时间漂移。声音听感和技术解码通过分开记录。

## 工具与记录

```bash
# 退出码2表示筛到需要复核的片段；报告写入作品自己的质量目录。
python3 "$S/scripts/audio_endings.py" audit "$P" --output "$P/quality/audio-endings.json"
# 仅在实际试听确认完整后，生成独立缓冲副本；不会覆盖原音频。
python3 "$S/scripts/audio_endings.py" pad "$ORIGINAL" "$DERIVATIVE" --review "$END_REVIEW"
```

试听记录JSON包含`audio_sha256`（实际试听的原音频hash）、`status="listened_complete"`与`notes`（核对的末句、是否完整及实际试听结论）。只检查波形或ASR时不得写此状态。`pad`生成`.end.json`追溯原音频、输出、试听记录与补入时长；来源或试听记录改变后须重审。

项目镜头可用`audio_end_review`指向当前音频的完整末句试听记录；有`processing`的派生音频若原始音频被标记，则通过`source_end_review`关联原音频试听记录。原始配音必须保持不可变，不能在原文件上加零后沿用旧hash认可。已有视频不因工具更新自动重做；本次修复作为新制作的前置门槛，不回写既有交付物。
