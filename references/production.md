# 生产与改动策略

## 哪些改动需要重做什么

| 改动 | 处理 |
|---|---|
| 台词、声音模型/参数或参考音频 | 重做相关配音；再build、render、verify、看图试听并review |
| 图解参数、章节或镜头结构 | build相关章，重渲与检查 |
| 自定义源脚本 | 默认共用custom.js；章专属脚本用chapter.custom_script。修改后仅重建、重渲与检查引用该源文件的章节 |
| 原始音频文件或对齐文件 | build检测内容hash变化；重新渲染与检查 |
| 只改文件外部说明 | 不应为文档编辑重做画面 |

配音缓存包含讲稿、声音参数、模型文件元数据、运行库版本与音频hash；仅复用匹配的产物。模型权重身份使用文件大小与修改时间及config摘要，不等同于逐字节全模型校验；严格复现实验可另保存权重hash。

构建、渲染、检查、人工/助手审核分别有记录。日志只是诊断信息，不能当阶段完成标志。只允许使用当前画面/音频hash对应的检查与审核；merge拒绝未审核或已过期的章节。

原音频经过停顿处理时保留raw_audio及processing记录；build检查处理前后hash、讲稿和节奏配置，不能把处理后音频无来源地当外部输入。生成的章节文件不是源文件，布局修正必须回写项目自定义源脚本。

## 句尾与转场音频门槛

每个新合成段按[audio-endings.md](audio-endings.md)筛查原始结尾、核对末句，再决定重生成或补收尾缓冲。不能把0.12秒镜头间静音当作末句完整性修复。build与check_build会拦截未解决的疑似硬收尾或不足0.35秒的缓冲。升级不自动重做已有视频，也不把旧的技术检查当新声音门槛已通过。

## 自然配音

- 不用系统朗读代替用户要求的自然TTS。用户已认可声音后，优先沿用其实际参数，仍要试听新台词。
- 设计音色每段独立合成可能有细微差异。当前实现不承诺身份一致；长章节可选择外部连续配音加可靠对齐。固定男声使用内置 approved-male-v1 档案和 Base 模型参考克隆，不能把相同seed当克隆。
- 短试听选声与长片合成是不同验收阶段。检查句尾截断、重复、漏字、奇怪停顿、术语读音、音色跳变和音量，而不仅是WAV文件存在。
- 未经用户同意，不把已确认的声音或内容发送到另一个云端服务。

## 时间与字幕

关键动作按[语音与视觉协同](narration-visual-sync.md)绑定语句及对象时间，不用全段比例代替卡点。镜头边界根据真实音频确定，不按固定字数猜整段长度。默认句内边界仍按长度估计；读字卡点、数字出现、精细动作应使用核对后的事件或外部对齐。配音变速后需按新音频重建所有时间，不能只替换音轨。

可选的上游`vendor/字幕.mjs`适用于已有音频的单独转写：有本地whisper-cli及模型时走识别时间；没有时可用稿件和静音检测回退。把实际字幕条转换成项目的alignment文件再build。不得把回退结果标成ASR或精确字级对齐。通用原稿匹配与选择性停顿流程另见[natural-narration.md](natural-narration.md)；它可接收外部时间或明确配置的本地faster-whisper模型，不隐式安装。

## 内容检查不是刷像素指标

- 视觉关系应与台词一致：先后、方向、加权、因果、计数和对比不能画反。
- 镜头需要停住让观众读时可以停；低像素变化只触发复核。不要为了变化分数挪动整幅图而不增加解释。
- 数据图有单位、基准、来源；虚构数字和示意图明确说明。
- 关键标签、读数和字幕在缩小预览后仍可读；不要用快速裁切掩盖溢出。
- 现有scene类型不能表达概念时，设计custom机制，而不是强行套现成图解。

## 交付状态

技术检查通过与实际内容审核分开记录。review必须附已看过的成片抽帧或扫片文件，以及对声音和字幕的真实判断。声音未试听时保留pending，合并结果会标为preview_pending_audio_review；这允许先看预览而不虚报成片听感已审核。只能报告实际做过的检查。若检查发现问题，修复受影响章后重跑，最多先做两轮有依据的修复；问题仍未解决则交代具体局限，不无限重渲。

内置工具不自动判断事实正确、不自动听出TTS漏字，也不自动证明图解讲清楚。交付说明保留这些验证边界。
