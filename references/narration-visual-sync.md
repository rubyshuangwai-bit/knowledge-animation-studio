# 语音与视觉协同

目标：观众听到一句话时，能自然找到对应对象、看到相关变化，并理解与前后内容的关系。不是单纯增加画面复杂度。

## 分镜与执行

- 讲稿中的每个解释单元，明确：口播语句、所指对象、要理解的关系或变化、当前视觉动作、需要弱化的背景、时间依据。无需每句话都切镜或增加动画；定义与阅读停留也可保留静止画面。
- 按知识依赖展开信息。首次引入先定位对象，再展示关系；过程用前态、动作、后态解释，不能直接铺满最终结构让观众自己找。
- 当前讲解对象用提亮、框选、局部标记、沿线流动等适合关系的方式指向。其他信息适度降权，同时保留必要上下文。同一对象的位置、标签与颜色尽量连续，避免无意义跳动。
- 数量、比较、共享、因果等关系，应有相应视觉证据；不要用装饰性位移替代机制解释。演示“结构变化”时注明是示意，不让动画暗示真实系统不存在的运行过程。
- 图中说明、标题和字幕应分工，避免重复长句同时争夺注意力。动画不要求全屏持续运动，必要停留用于理解。

## 配音时间

先有分镜的语义顺序，配音完成后再绑定关键动作的秒数事件。可用已核对的人工时间、ASR词/句时间或强制对齐结果；注明方法和误差。不要把按文本长度分配的时间说成实测发音时间。

关键对象出现、焦点切换与连线动作要对应实际音频片段，不仅对应整段百分比。展示需要更长停留时，先调整镜头密度或合理停顿，再重建时间线，不能靠赶动作掩盖问题。

现有build支持外部alignment JSON；句内字高亮仍插值。可用通用脚本`prepare_narration.py`提取或接收原音频时间记录，再匹配原稿、处理语义停顿并更新事件；参数与边界见[自然讲述](natural-narration.md)。语义单元和停顿位置仍由助手设计，工具不自动理解教学含义。既有GQA案例使用本机faster-whisper small提取词时间后整合为句界；此为已验证路径，不强制所有项目使用同一模型，缺依赖时明确处理，不隐式安装。

## 验收

先抽取机制复杂的短段验证，再扩展到其余章节。核对以下问题：

1. 听到对象名时，当前对象是否可直接定位，而不必搜索全图？
2. 声音开始解释新关系时，画面是否仍在建立上一关系？
3. 过程能否看见前后状态，关系方向、计数和边界是否正确？
4. 焦点是否随讲解转换，背景是否压过当前动作？
5. 静帧、扫片与连续播放结论是否分别记录，ASR时间误差与声音试听状态是否如实保留？

用户认可某一段的理解效果，仅适用于该段及方法方向，不代表整片其他段落已验收。保留旧版供比较，局部改动先只重做受影响段。抽样数量、时长与高亮形式按内容决定，不复制案例固定秒数或技术名词。

用`studio.py preflight`抽取每个语义单元的中点静帧，检查是否遗留上阶段标签、出现文字叠加或焦点错误。输出manifest记录捕获范围，仍需实际看图；随后用代表样片和成片扫片检查过渡，不将静帧通过等同于声音与动作同步已验收。
