# 自然讲述、语义停顿与时间更新

适用于新口播，或用户反馈“像念提纲、短句密集、没有停顿”的改稿。固定参考音色解决说话人条件，不能单独解决讲述方式；参考克隆也不等于可验证的情绪、重音控制。

## 先写一段能连续听懂的话

围绕一个问题组织完整意思，补上必要的前提、承接和因果关系。可以用“先看哪里—发生什么—意味着什么—有什么边界”带观众理解；只在确有教学作用时提问，不把所有主题强制写成固定套路。删去提纲式连续报点，术语首次出现先给可理解的对象或动作。保留来源、适用条件与代价，不为口语化编造技术背景。

口播按完整意思连续表达；字幕按阅读长度分条；动画按语义单元切换。三者不必一一对应：一个镜头可以包含多个语义单元，一个单元可以包含多条字幕。不要把短字幕直接变成独立TTS短句，也不必整章一次合成；在模型稳定的完整知识段边界合成，检查段首段尾与接缝。

先朗读改稿，判断只听声音能否理解。自然口语可能增加时长，应说明估计变化；不为维持旧秒数压缩停顿或擅自整体变速。最终时长以实际音频为准。

每个合成段的末句和转场收尾先按[句尾完整性](audio-endings.md)检查。语义停顿工具不负责恢复未生成的末字，全文ASR匹配也不能替代句尾完整性试听。

## 停顿有教学目的

保留模型已有停顿，只在概念转换、需要思考的问题、比较和结论等位置按需补足。示例目标间隔可为约0.6–0.9秒，但不是所有项目的固定值；按语义和实际声音设置。不要在每个逗号或句号后机械插静音。

先确定语义边界，再检查该处实际间隔；只补缺口，在低能量位置插入。没有可信的安静切点时复核边界或重做该段，不强切人声。保留不可变原音频，派生处理后音频；不把上次处理结果再当原音频重复加停顿。所有受影响的字幕、动画事件及关键词时间一起更新，重新构建受影响章节。

## 可执行工具

`scripts/prepare_narration.py`处理任意主题，不含固定领域词表或镜头号。输入是项目、每镜头的原音频`raw_audio`、语义单元、可选停顿与原音频时间记录；输出独立WAV、字幕alignment、事件和处理追溯。字段见[项目协议](project-format.md)。

```bash
# T为原音频时间记录目录，结构为 <chapter>/<shot>.json。
python3 "$S/scripts/prepare_narration.py" "$P" --timings "$T"
# 检查 prepared/project.json 和处理记录，首次接入时才加 --apply。
python3 "$S/scripts/prepare_narration.py" "$P" --timings "$T" --apply
# 使用明确指定的本地识别模型时，在装有faster-whisper的Python环境执行：
"$ASR_PYTHON" "$S/scripts/prepare_narration.py" "$P" --model "$LOCAL_ASR_MODEL"
```

工具不会安装依赖、下载模型或上传声音。可用`--chapter`选章。默认只写`prepared/`，不会替换项目配置。`--apply`保留首次接入前的配置；已有备份时停止，避免无意覆盖。后续迭代先检查备份与新预览配置，再明确更新配置，不删除备份来盲目重试。

处理记录包括原音频和输出hash、讲稿hash、识别记录hash、参数、处理器hash、实际补入静音及更新后的事件。处理后的音轨仍保留来源，不能因`generated_audio=false`而丢失生成/处理证据。它不自动证明音色、发音或听感合格。

## 识别失败先分清原因

优先使用原稿匹配识别时间，不直接把识别文字当最终台词。繁简差异可用`--normalize-chinese`统一后匹配，需要当前Python已有OpenCC。匹配覆盖率只是定位指标，不是声音验收分数。

遇到重复文本、低覆盖、零时长词或异常长段，先看识别结果，再核对原音频。零时长词不作为可靠匹配时间，工具在processing.json内记录警告；其字符按缺失时间处理，必须复核，不能声称这些词已准确定位。可用`--retry-asr --model ...`无提示词分块独立识别，保留两次记录；按问题选择是否复核术语、繁简、漏字或TTS异常。不要把ASR幻觉直接判成配音重复，也不要为提高匹配率自动删改讲稿。无法可靠定位时停止接入，提供核对后的人工边界或重做受影响段。

未匹配字符和词内字时间仍是插值。字幕与语义单元可通过检查，但只有实际试听才能判断声音是否自然；样段认可不等于完整新台词已听过。
